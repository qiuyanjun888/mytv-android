# 直播换台起播缓冲优化设计

**目标**

降低频道切换时客户端等待 `READY` 的时间，统一改善直播与回看进入播放器后的起播卡顿。

**现状**

- 当前播放器换台后首帧很快能出，但 `BUFFERING -> READY` 会稳定等待约 2.5 秒以上。
- 该等待更像 Media3 默认起播缓冲门槛，而不是 FCC 服务端切流慢。
- 当前仓库里还没有完整接好的回看播放入口，但只要后续回看也走同一个播放器 `prepare()`，统一的起播缓冲优化就会生效。

**范围**

- 新增一个独立的 Media3 起播缓冲策略。
- 统一下调播放器起播与重缓冲恢复门槛。
- 将策略接入 `LeanbackMedia3VideoPlayer` 的播放器构建过程。

**不在范围内**

- 不修改 IPTV 源解析格式。
- 不新增回看 UI 或补完回看业务入口。
- 不引入双播放器预热或无缝切换。

**方案**

1. 抽出 `Media3LoadControlPolicy`，集中维护“快速换台”所需的起播缓冲参数。
2. 保持 `minBufferMs`、`maxBufferMs` 等主体缓冲策略不变，只降低 `bufferForPlaybackMs` 与 `bufferForPlaybackAfterRebufferMs`。
3. 在创建 `ExoPlayer` 时直接挂载该 `LoadControl`，让所有进入当前播放器的频道切换都受益。

**风险**

- 起播门槛降低后，弱网环境下更容易出现“先出画面、随后短暂二次缓冲”的情况。
- 由于当前仓库没有完整回看入口，本次只能保证播放器层具备同样的快速起播能力，不能声称现有回看功能已端到端验证。

**验证**

- 单元测试覆盖快速起播参数值，并确认主体缓冲参数仍保持默认。
- 本地构建通过。
- 真机抓日志确认换台后 `READY` 不再稳定卡在约 2500ms 缓冲门槛。
